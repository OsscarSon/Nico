## A11 交换机与路由器（约 14 分钟）

**Hook**：同教室递纸条与跨楼送信，为什么要不同地址和中转点？目标是区分链路上的 MAC、网络定位的 IP、交换机、路由器和默认网关。

四段讲解目标：① MAC/IP 回答不同问题，MAC 不等于永久不变的设备身份；② 交换机从源 MAC 学入口，未知目标单播泛洪但不改成广播地址；③ 用子网决定直接送达或先送网关，路由器查目标 IP 并重封装 MAC，端到端 IP 在无 NAT 时不变；④ ARP、广播、路由选择的模型边界。

**Network Forwarding Lab**：两个 /24 LAN、四台电脑、两个交换机和双接口路由器。自由选择源/目标及自动、强制直送或强制网关，逐跳处理帧队列，观察实际学习表、IP/MAC、TTL、接收/丢弃日志和路径。冷表与热表可以对照；错误远端直送不会出 LAN。

| 挑战 | 必须产生的状态证据 |
| --- | --- |
| A→B 同 LAN | 实际交付 B，通道处理完，无 R 路径 |
| A→C 跨 LAN | 实际交付 C，路径经过 R，IP 与最终 MAC 正确 |
| B→A 冷表 | 实际未知单播泛洪证据及正确本地交付 |
| D→B 默认网关 | 首帧目标 MAC 为 LAN2 网关，经 R 实际交付 B |

不是计点击次数：判分检查交付端点、IP、最终 MAC、完整路径、是否路由及泛洪/首跳证据。每任务重置其状态，不能沿用上一任务的通过标记。

三道诊断题针对：从目标 MAC 学习的误解、跨网段首跳 MAC/IP 混淆、未知单播误当广播。迁移题换成另一组 LAN，计算经过一个路由器的两次链路封装（答案 2）。先修 A09/A10，建议下一课 A12。

**简化**：ARP 查询/广播/响应由预知 IP→MAC 表提供；没有真实 ARP 报文。仅两条直连 /24 路由，无 NAT、VLAN、STP、老化、动态路由或环路；并非完整以太网/IP 实现。来源：RFC 826（ARP）、RFC 1812（IPv4 路由器）、RFC 4188（桥接/FDB 管理定义）。

## A12 数据包：切开、编号、再拼起来（约 13 分钟）

**Hook**：朋友发来的拼图纸条被打乱且少一片，能不能可靠复原？四段讲解目标：① 为什么大消息要拆成可管理小块；② 编号区分发送顺序和到达顺序；③ 缺失不能靠猜测恢复；④ 应用消息块、IP 分片和 TCP 字节流是不同层次。

**Packet Reassembly Lab**：输入 1–36 个 Unicode 码点，按 2–8 码点分块，输入 uint32 种子生成可复现乱序。每块编号、内容可查，逐块投递/丢失；接收端上移/下移实际片段，不提供自动排序。缺片可请求重发；只有收到片段的序号连续、数量/内容正确且顺序正确时才拼接输出。缺片时 `text: null`，绝不返回原文作假重组。

挑战一：种子 17，实际乱序到达后手动重排并恢复。挑战二：种子 44，实际丢片、排空通道并观察重组失败，再重发缺片、手动排列和恢复。判分使用实际到达序列、观察缺失、回收片段记录与当前内容；空操作、自动读取发送原文、错序或旧成功结果均不能通过。

三道诊断题针对：按到达顺序拼接、缺片猜字、误把教学编号当 TCP 包号。迁移题：17 码点信息每块最多 4 码点，需 5 块。先修 A09/A11，下一课 A13。

**简化**：这是应用层教学编号消息块，不是实现 IP 分片，也不是 TCP 段。码点不是 UTF-8 字节或完整字素簇；真实协议需要长度、标识、校验、边界和重传机制。TCP 按字节编号且不保留应用写入边界。来源：RFC 791、RFC 9293。

## A14 TCP：三次握手与可靠传输（约 15 分钟）

**Hook**：发出作业不等于老师收到，确认又丢了怎么办？四段讲解目标：① SYN/SYN-ACK/ACK 与两端不同的建立时刻；② SYN 消耗序号、纯 ACK 不消耗，序号按字节、ACK 指向下一期待连续字节；③ 丢失/延迟/超时重传、重复数据不重复交付；④ 可靠有序与应用业务成功的区别，停等模型和真实 TCP 的范围。

**TCP Connection Lab**：客户端、服务器、手动网络通道。启动三次握手后逐报文投递、丢弃、延迟；展示双方状态、seq/ack、待确认段、实际应用收到文本。连接建立后发送至多 3 ASCII 字节的数据段。每次推进一个逻辑时刻，等待 3 时刻才能重传到期原报文（保持 seq/内容）。ACK 丢失重传会去重，重复 SYN-ACK 再确认，异常方向/序号不会推进有效状态。数据段带 ACK 标志；UI 的“数据段/数据确认”是角色说明，不伪造 TCP 标志位。

| 挑战 | 判分证据 |
| --- | --- |
| 正常连接与传输 | 无丢包；双方 ESTABLISHED、原文仅一份、所有字节确认 |
| 握手丢包与恢复 | 实际丢 SYN、SYN-ACK 或最终 ACK；实际握手超时重传；最终完整传输 |
| 数据丢包与恢复 | 实际丢数据或数据 ACK，实际原段重传；最终原文/确认量/期待序号一致 |

允许不同丢包点与操作顺序，判分不依赖固定点击脚本。正常/错误/重复/过早重传/延迟等从状态机推导结果。

三道诊断题针对：最终 ACK 丢失时双方状态误判、ACK 差一/包数误解、重复数据重复交付。独立迁移题：已建立连接首字节 1001，共 5 字节，下一 ACK=1006。先修 A09/A12/A13；下一课 A15 保持“筹备中”，不虚构可访问课程。

**简化**：固定 ISN 100/500、ASCII 1–12 字节、单向数据、单个未确认数据段；不缓存乱序数据，不含滑动窗口、拥塞控制、校验和、RTT/RTO 自适应、真实计时器、序号回绕、FIN/关闭或重试失败上限。并非完整 TCP 协议栈，不发送真实网络数据。来源：RFC 9293、RFC 6298。
